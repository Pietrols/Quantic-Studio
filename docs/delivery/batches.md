## B1 product demonstration

Use an original small industrial feeder with declared synthetic parameters, not client data. Create equipment through forms; connect and validate; choose source and operating state; save; run native balanced load flow; display voltages, currents, directional power and losses; select a result to inspect its input and equation; change a load and visibly invalidate results; rerun; export a report and reopen the project. Include invalid data, nonconvergence, failed API request, save conflict and unsupported equipment.

Its task packages must cover UI forms, project/layout persistence, result identity, native API routing and end-to-end tests, rather than shipping a working solver behind an unusable front end. Existing adapter routing must remain available for reference comparison with explicit solver labels.

## Mandatory per-family test design

- Load flow: KCL and power balance, Jacobian finite-difference checks, PV/PQ bounds, transformer orientation, island references, divergence and singularity.
- Faults: positive/negative/zero-sequence separation, phase reconstruction, neutral impedance, source-current orientation, RMS/peak distinction and contribution aggregation.
- Motors: electrical and mechanical assumptions, torque/inertia units, acceleration sign, stall/trip distinctions, step-size refinement.
- Harmonics: original RLC oracle, frequency-dependent parameters, phase cancellation, denominator provenance, singular resonance handling.
- Protection/arc: readable curves and editions, measurement conventions, relay plus breaker time, validity-range rejection and no unverified safety verdicts.
- Dynamics: initialization residual, no-event equilibrium, state/event ordering, fault clearing, timestep refinement and repeatable restart.
- OPF/planning: objective units, constraints independently re-evaluated, infeasibility distinguished from solver failure, no global-optimum claim for a heuristic.
- Import/report: no execution of imported code, format/version limits, IDs/units/topology round-trip checks, loss report, report linked to immutable run hash.

## Delivery cadence and rework

Large campaigns run without a user prompt at each WP. Each PR contains a coherent result and ordered commits, with independent code-quality, engineering and implementation-quality reviews. Keep at most two completed PRs waiting for external review as an initial queue policy; manager may reduce this when rework accumulates. This is a workflow limit, not a compute benchmark.

Independent next work starts on accepted main. If work must stack, record parent PR and SHA; it remains draft and cannot merge before its dependencies. After parent changes or rebasing, rerun affected checks and refresh reviews. A failed engineering gate stops dependent work but not unrelated research/UI preparation.

Small reviewer fixes belong in the same PR with regression evidence and renewed review of affected changes. Larger findings return to the manager as numbered tasks: severity, file/requirement, reproduction, expected behavior, acceptance test and dependency impact. Never merge on silence, an emoji acknowledgement, or a missing review.
